# PR08 — Mejora de visibilidad y accesibilidad en el acceso

## Contexto

La ruta `/login` mostraba únicamente dos campos y un botón, sin una composición visual que los separase del fondo oscuro ni una jerarquía de contenido clara. El formulario quedaba situado en la parte superior de la página y el pie legal competía con la tarea principal.

## Cambios realizados

- Se ha creado una pantalla de acceso centrada con una tarjeta de ancho máximo de 448 px, superficie diferenciada, borde, sombra y espaciado adaptable.
- Se han añadido el logo del club, un enlace de regreso a la portada, título y texto de contexto.
- Los campos ahora tienen etiquetas visibles, `autocomplete` apropiado y estados de foco perceptibles.
- Se ha añadido el control para mostrar u ocultar la contraseña.
- El botón de acceso ocupa todo el ancho de la tarjeta y comunica su estado de carga.
- Los mensajes de error y éxito se anuncian mediante regiones accesibles (`alert` y `status`) y no exponen detalles técnicos de autenticación.
- Se ha implementado la recuperación de contraseña mediante Supabase, con retorno a `/auth/update-password`.
- La recuperación usa el flujo implícito para que el enlace pueda abrirse en otro dispositivo; los enlaces PKCE emitidos antes de este cambio deben regenerarse.
- Se ha incorporado un enlace de ayuda hacia `/join`.
- El layout raíz ahora usa una columna de altura mínima de pantalla; el contenido principal crece antes del footer para que este quede al final sin desplazar el formulario.

## Validación

- `npm run lint` — correcto.
- `npm run build` — correcto.
- Verificación visual local de `/login` — carga con contenido, sin overlay de errores y con los controles esperados visibles.
- Flujo de recuperación — se muestra la vista de recuperación y su botón de envío.
- `npx playwright test tests/e2e/auth.spec.ts --project=chromium` — 5 pruebas superadas.

## Nota de configuración

`supabase/config.toml` renombra el servicio local de correo de `inbucket` a `local_smtp`, nomenclatura admitida por la CLI local instalada (v2.113). Si el proyecto activa Supabase Branching o su integración de GitHub, debe comprobarse la compatibilidad del servicio alojado antes de habilitar esa integración: Supabase mantiene una incidencia abierta sobre ese parser.

## Resultado esperado

Al abrir `/login`, el propósito de la pantalla y el formulario se identifican de inmediato tanto en escritorio como en móvil. El acceso, la recuperación de contraseña y las rutas de ayuda permanecen disponibles mediante teclado.
