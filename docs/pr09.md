# PR09 — Recuperación de contraseña con correo propio

## Implementación

- El formulario de acceso solicita la recuperación mediante `POST /api/auth/reset-password`.
- La API limita solicitudes por IP y email, genera el token de recuperación con la service-role key y mantiene una respuesta neutra para evitar enumerar cuentas.
- El email usa la cadena de entrega existente: Resend cuando está disponible y EmailJS como fallback. La clave de idempotencia se deriva del token de un solo uso.
- El enlace apunta directamente a `https://cejoventut.com/auth/callback?token_hash=…&type=recovery`, sin usar el mailer, PKCE ni los Redirect URLs de Supabase.
- El callback usa `verifyOtp`, guarda la sesión y redirige al formulario de nueva contraseña.
- Los enlaces inválidos, usados o caducados muestran una explicación segura para solicitar otro.

## Configuración requerida antes del despliegue

- Configuración de EmailJS (`EMAILJS_SERVICE_ID`, plantillas y claves), ya disponible en Production.
- Resend es opcional mientras `cejoventut.com` no esté verificado; al verificarlo volverá a actuar como proveedor principal cuando `EMAIL_PROVIDER=resend`.

## Validación

- Pruebas unitarias de solicitud válida, usuario inexistente, límite de frecuencia y fallo de entrega.
- `npm run lint`
- `npm run build`

## Resultado

La recuperación deja de depender del mailer estándar y la Site URL de Supabase. El enlace funciona en cualquier dispositivo y solo puede consumirse una vez.
